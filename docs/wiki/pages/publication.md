- **GitHub Pages** : `ci.yml` construit `riftbound/train/build/` (Pyodide 0.26.4 via npm) et le publie depuis `main` si les tests passent. Réglage unique : Settings > Pages > Source = GitHub Actions. Sans base claude.ai, la page affiche « Partie non enregistrée ».
- **Artefact claude.ai** (republié le 2026-10-28, demande de l'utilisateur : « une version artefact et garder la version GitHub Pages ») : https://claude.ai/artifact/5FfNwvwKnVbFY4dbQbxjwR (privé, capacité `db`). Chaque partie, avec les coups de l'IA et les erreurs marquées, s'enregistre seule dans la collection `games` ; Claude la lit avec l'outil ArtifactData (`list`, `out_dir` -> fichiers JSON), puis `engine/banc/humain.py <dossier>`. Publication en deux passes (255 fichiers au plus par passe) : page + moteur + images + sons « Cartes » (142 fichiers), puis les six autres ambiances sonores (126). Pas de lecteur de replays (`games/`, 27 Mo) ni de téléchargement « Mes parties » (l'artefact refuse les téléchargements sans la capacité `downloads`). Pas de `py/bytecode.json` si `build.sh` tourne sans node (Windows) : chargement plus lent. Étapes et pièges : `docs/REPRISE.md` §3. Chargement et enregistrement dans l'artefact : **non vérifiés** au 2026-10-28 (navigateur intégré non connecté à claude.ai).
- Copie maîtresse de la page : `riftbound/train/src.html` (+ `base.css`) ; `build.sh` assemble.
- **Python précompilé** (2026-10-17) : `build.sh` lance `train/precompile.mjs` (node + le Pyodide de `pyodide-cache/`). Les modules de la stdlib que la table charge passent en `.pyc` dans `python_stdlib.b64.txt` (les autres restent en `.py`) ; le moteur est livré en `.py` **et** en bytecode (`py/bytecode.json`, `.pyc` « checked-hash » : Python recompile si le `.py` diffère, jamais de bytecode périmé). Sans node, `build.sh` prévient et livre la stdlib d'origine ; sans `bytecode.json`, le worker compile les `.py` comme avant. Le worker télécharge tout en parallèle du wasm. Mesure : `docs/memoire/riftbound-training-table.md` (« Chargement »).
